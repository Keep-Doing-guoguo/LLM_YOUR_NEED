# YOLO 训练内容与机制讲解

本文集中解释 YOLO 训练过程中常见的参数和名词。重点不是某一个版本的完整训练脚本，而是把训练时反复出现的概念讲清楚：`epoch`、`batch`、`imgsz`、`lr`、`anchor-based`、`anchor-free`、正负样本分配、IoU、loss、NMS、DFL、TAL、SimOTA 等。

可以先把 YOLO 的训练流程理解成下面这条链路：

```text
图片和标注
  -> 数据增强
  -> resize / letterbox
  -> 模型前向
  -> 生成候选预测点或 anchor 预测
  -> 标签分配，确定正负样本
  -> 计算 box/class/objectness/DFL 等 loss
  -> 反向传播
  -> 更新模型参数
```

推理时不再有标签分配和 loss 计算，只保留：

```text
图片
  -> 预处理
  -> 模型前向
  -> 解码预测框
  -> 置信度筛选
  -> NMS 或 NMS-free 后处理
  -> 最终检测框
```

## 一、训练常见参数

### 1. epochs

`epochs` 表示完整遍历训练集多少轮。

```text
epochs = 100
```

如果训练集有 10000 张图片，`epochs=100` 表示模型理论上会看完整训练集 100 次。

影响：

| 设置 | 可能现象 |
|---|---|
| 太小 | 模型没收敛，欠拟合 |
| 适中 | loss 稳定下降，验证集指标提升 |
| 太大 | 训练集越来越好，验证集变差，过拟合 |

小数据集更容易过拟合，通常要配合数据增强、预训练权重和 early stopping。

### 2. batch / batch_size

`batch_size` 表示一次训练送入模型的图片数量。

```text
batch = 16
```

batch 越大：

- 显存占用越高；
- 梯度更稳定；
- 单步统计更可靠；
- 可能需要适当增大学习率。

batch 越小：

- 显存压力小；
- loss 波动更明显；
- BatchNorm 统计可能不稳定。

### 3. imgsz / img_size

`imgsz` 表示训练输入图像尺寸。

```text
imgsz = 640
```

常见 YOLO 输入尺寸：

```text
416, 512, 640, 960, 1280
```

尺寸越大：

- 小目标更容易被保留；
- 显存和计算量更高；
- 训练和推理更慢。

尺寸越小：

- 速度快；
- 显存低；
- 小目标容易丢失。

如果任务中有大量小目标，通常不要把 `imgsz` 设得太低。

### 4. lr / learning rate

学习率决定参数每次更新的步子有多大。

```text
lr0 = 0.01
```

常见问题：

| 学习率 | 现象 |
|---|---|
| 太大 | loss 抖动、发散、mAP 上不去 |
| 太小 | 收敛慢，训练很久也没效果 |
| 合适 | loss 下降平稳，验证指标提升 |

YOLO 中经常会看到：

```text
lr0: 初始学习率
lrf: 最终学习率比例
```

例如 `lr0=0.01, lrf=0.01`，表示最终学习率可能衰减到初始学习率的 1%。

### 5. optimizer

优化器负责根据梯度更新模型参数。

常见优化器：

| 优化器 | 说明 |
|---|---|
| SGD | 传统 YOLO 常用，泛化稳定 |
| Adam | 自适应学习率，收敛快 |
| AdamW | Adam 加解耦 weight decay，现代训练常用 |

在目标检测中，SGD 和 AdamW 都很常见。具体选择取决于框架默认配置、batch size 和数据规模。

### 6. momentum

momentum 是动量项，用于让梯度更新更平滑。

```text
momentum = 0.937
```

它可以理解为“当前更新方向会参考过去一段时间的梯度方向”，减少训练抖动。

### 7. weight_decay

`weight_decay` 是权重衰减，用于正则化，防止模型参数过大。

```text
weight_decay = 0.0005
```

作用：

- 降低过拟合；
- 提升泛化；
- 对小数据集尤其有用。

### 8. warmup

warmup 表示训练开始阶段先用较小学习率，再逐渐升到目标学习率。

```text
warmup_epochs = 3
```

训练刚开始时模型输出不稳定，如果直接用大学习率，容易震荡。warmup 可以让训练更平稳。

### 9. patience / early stopping

`patience` 表示验证集指标连续多少轮没有提升就提前停止。

```text
patience = 50
```

它用于防止无意义地继续训练，尤其适合小数据集。

### 10. workers

`workers` 表示 DataLoader 使用多少个进程读取数据。

```text
workers = 8
```

workers 太低，GPU 可能等数据；workers 太高，CPU 和内存压力会变大。

### 11. device

`device` 指定训练设备。

```text
device = 0
device = 0,1,2,3
device = cpu
```

多卡训练时，有效 batch size 通常等于：

```text
batch_per_gpu * gpu_num
```

## 二、数据增强相关名词

YOLO 系列非常依赖数据增强。数据增强可以提高泛化能力，尤其是在数据量不大、场景复杂时。

### 1. Mosaic

Mosaic 会把 4 张图片拼成 1 张：

```text
image A | image B
--------+--------
image C | image D
```

优点：

- 增加目标尺度变化；
- 增加背景组合；
- 提高小目标出现概率；
- 提升模型对复杂场景的鲁棒性。

缺点：

- 训练后期如果一直使用，可能让数据分布和真实推理图像差异过大；
- 很多实现会在最后若干 epoch 关闭 Mosaic。

### 2. MixUp

MixUp 会把两张图片按比例混合：

```text
new_image = λ * image1 + (1 - λ) * image2
```

标签也按比例混合。

它能提升泛化，但目标检测中使用要谨慎，因为过强的混合可能影响边界框学习。

### 3. Copy-Paste

Copy-Paste 会把一个图片中的目标复制到另一个图片中。

常用于：

- 小目标；
- 罕见类别；
- 实例分割；
- 数据不足场景。

### 4. HSV / 色彩增强

常见参数：

```text
hsv_h: 色相扰动
hsv_s: 饱和度扰动
hsv_v: 亮度扰动
```

作用是让模型对光照、颜色变化更鲁棒。

### 5. Random Flip

随机翻转：

```text
fliplr: 左右翻转概率
flipud: 上下翻转概率
```

自然图像中左右翻转常用，上下翻转要看任务。例如行人、车辆、交通标志任务通常不适合随便上下翻转。

### 6. Multi-scale Training

多尺度训练会在训练过程中随机改变输入尺寸。

```text
imgsz 在一定范围内变化
```

作用：

- 提升模型适应不同输入尺寸的能力；
- 增强尺度鲁棒性。

## 三、Anchor-Based 是什么

Anchor-based 是基于预设框的检测方式。YOLOv2、YOLOv3、YOLOv4、YOLOv5 早期版本都属于典型 anchor-based 检测器。

### 1. Anchor 的含义

Anchor 是预先设定的一组框尺寸，例如：

```text
(10,13), (16,30), (33,23)
(30,61), (62,45), (59,119)
(116,90), (156,198), (373,326)
```

这些框不是最终预测框，而是预测框的参考模板。

模型实际预测的是相对于 anchor 的偏移：

```text
预测框 = anchor + 网络预测的偏移量
```

### 2. Anchor-Based 的输出方式

假设某个检测层大小为 `80x80`，每个网格有 3 个 anchor，类别数为 80，则输出通道为：

```text
3 * (4 + 1 + 80) = 255
```

其中：

| 项 | 说明 |
|---|---|
| 4 | bbox 坐标参数 |
| 1 | objectness |
| 80 | class probability |

输出形状可以理解为：

```text
[H, W, anchor_num, 5 + num_classes]
```

### 3. Anchor 如何匹配 GT

训练时，每个真实框需要分配给某个 anchor。

典型流程：

```text
Ground Truth Box
  -> 计算它与所有 anchor 的宽高 IoU
  -> 找到最匹配的 anchor
  -> 根据 GT 中心点找到 grid cell
  -> 该 grid cell 上该 anchor 变成正样本
```

这里的 IoU 通常只比较宽高形状，不比较绝对位置。

### 4. Anchor-Based 的优缺点

优点：

- 训练早期更稳定；
- 对不同目标尺度有先验；
- 在 YOLOv2-v5 中工程成熟。

缺点：

- 需要设计或聚类 anchor；
- 数据集变化后 anchor 可能不适配；
- 输出候选框数量多；
- 标签分配规则复杂；
- 对极端长宽比目标可能需要重新聚类。

### 5. AutoAnchor

AutoAnchor 会根据当前数据集标注框自动聚类 anchor。

```text
训练集 GT boxes
  -> K-Means / 遗传算法
  -> 得到适合当前数据集的 anchors
```

如果数据集目标尺寸和 COCO 差异很大，重新聚类 anchor 往往有帮助。

## 四、Anchor-Free 是什么

Anchor-free 不再依赖预设 anchor 尺寸。YOLOv6、YOLOv8、YOLOv10 等现代 YOLO 版本常使用 anchor-free 思路。

### 1. Anchor-Free 的核心思想

不再让模型预测相对于某个 anchor 的偏移，而是让特征图上的点直接负责预测目标框。

常见形式：

```text
某个 grid point / anchor point
  -> 预测到框四边的距离 l, t, r, b
```

例如一个点 `(x, y)` 预测：

```text
left distance
top distance
right distance
bottom distance
```

最终解码成：

```text
x1 = x - left
y1 = y - top
x2 = x + right
y2 = y + bottom
```

### 2. Anchor Point

Anchor-free 里仍然可能出现 “anchor point” 这个词。

注意：anchor point 不是 anchor box。

| 名词 | 含义 |
|---|---|
| anchor box | 预设宽高框 |
| anchor point | 特征图上的参考点或中心点 |

Anchor-free 可以没有 anchor box，但仍然需要在特征图上生成参考点。

### 3. Anchor-Free 的优缺点

优点：

- 不需要手工设计 anchor 尺寸；
- 迁移到新数据集更方便；
- 输出和标签分配更简洁；
- 更适合配合 TAL、DFL 等现代训练机制。

缺点：

- 正负样本分配更依赖动态策略；
- 训练早期可能更依赖良好的 assigner；
- 对密集目标和尺度边界仍需要 carefully designed label assignment。

## 五、Anchor-Based 和 Anchor-Free 对比

| 对比项 | Anchor-Based | Anchor-Free |
|---|---|---|
| 是否需要预设框 | 需要 anchor boxes | 不需要 anchor boxes |
| 预测对象 | anchor 的偏移 | 点到边界距离或直接框参数 |
| 标签分配 | 常按 anchor 与 GT 匹配 | 常按中心区域、IoU、任务对齐得分 |
| 数据集迁移 | 可能需要重新聚类 anchor | 相对更方便 |
| 代表版本 | YOLOv2/v3/v4/v5 | YOLOv6/v8/v10 等 |
| 现代趋势 | 逐渐减少 | 越来越常见 |

需要注意：不同开源实现可能混合使用一些概念。例如某些版本叫 anchor-free，但内部仍会生成 anchor points；某些版本支持 anchor-based 配置但默认不用 anchor boxes。

## 六、正样本、负样本、Ignore 样本

目标检测训练中，不是所有预测位置都同等参与 loss。

### 1. 正样本

正样本是负责某个真实目标的预测位置。

在 anchor-based 中：

```text
某个 grid cell 的某个 anchor
  -> 被分配给某个 GT
  -> 正样本
```

在 anchor-free 中：

```text
某个 anchor point / grid point
  -> 被 assigner 分配给某个 GT
  -> 正样本
```

正样本通常参与：

- box loss；
- class loss；
- objectness loss，旧版 YOLO；
- DFL loss，现代 YOLO。

### 2. 负样本

负样本是不负责任何真实目标的预测位置。

负样本通常参与：

- objectness loss；
- class background 相关 loss，取决于具体实现。

负样本数量远大于正样本，所以检测训练里经常要处理正负样本不平衡。

### 3. Ignore 样本

Ignore 样本既不当正样本，也不当负样本。

典型情况：

```text
某个预测框不是最佳匹配
但它和某个 GT 的 IoU 比较高
```

如果强行把它当负样本，模型会被惩罚一个其实不错的预测。因此很多 YOLO 实现会把这类预测从 no-object loss 中忽略。

## 七、标签分配 Label Assignment

标签分配决定哪些预测位置负责哪些 GT。它是 YOLO 训练里非常关键的一步。

### 1. 固定分配

早期 YOLO 常用固定规则：

```text
GT 中心点落在哪个 grid cell
  -> 哪个 grid cell 负责
  -> 再选择最匹配的 anchor
```

优点是简单，缺点是正样本数量少，规则较硬。

### 2. 多正样本分配

后续版本会让一个 GT 分配给多个正样本。

好处：

- 增加正样本数量；
- 提高召回；
- 加快训练；
- 对小目标更友好。

### 3. ATSS

ATSS 是 Adaptive Training Sample Selection。

核心思想：

```text
根据不同特征层上的候选点与 GT 的 IoU 统计信息
自适应确定正负样本阈值
```

它比固定 IoU 阈值更灵活。

### 4. SimOTA

SimOTA 常见于 YOLOX 等检测器，也影响了后续 YOLO 的动态分配思路。

核心思想：

```text
对每个 GT
  -> 计算候选预测的 cost
  -> cost 综合分类损失和回归损失
  -> 动态确定 top-k 正样本数量
  -> 选择 cost 最低的一批预测作为正样本
```

可以理解为：不是固定每个 GT 分配几个正样本，而是根据当前模型预测质量动态选择。

### 5. TAL / Task-Aligned Assigner

TAL 是 Task-Aligned Assigner，YOLOv8、YOLOv10 等版本中常见。

它的核心是让分类和定位对齐：

```text
alignment_score = classification_score^alpha * IoU^beta
```

含义：

- 分类分数高；
- 框定位也准；
- 这类预测更适合作为正样本。

TAL 不是只看 IoU，也不是只看类别分数，而是同时考虑分类质量和定位质量。

## 八、YOLO Loss 组成

不同 YOLO 版本 loss 不完全一样，但常见组成可以概括为：

```text
total_loss = box_loss + cls_loss + obj_loss + dfl_loss
```

不是每个版本都有这四项。

### 1. box_loss

box loss 用于优化边界框位置。

常见形式：

| Loss | 说明 |
|---|---|
| MSE 坐标损失 | 早期 YOLO 使用 |
| IoU Loss | 直接优化框重叠程度 |
| GIoU | 无重叠时也能提供优化方向 |
| DIoU | 加入中心点距离 |
| CIoU | 加入重叠、中心距离、宽高比 |
| SIoU / EIoU | 一些实现中的进一步改进 |

现代 YOLO 通常使用 IoU 系列 loss，而不是简单 MSE。

### 2. cls_loss

分类损失用于判断目标类别。

常见：

```text
BCE Loss
Cross Entropy
Focal Loss
Varifocal Loss
```

YOLOv3 以后多标签分类常用 BCE，因为一张图中可以有多个类别，检测头对每个候选框独立判断类别概率。

### 3. obj_loss

objectness loss 用于判断当前位置是否有目标。

旧版 YOLO 常有：

```text
objectness = 当前 anchor / grid 是否负责一个目标
```

它不等同于类别概率。

最终置信度常见计算：

```text
score = objectness * class_probability
```

现代 anchor-free 或解耦头实现中，objectness 可能被弱化、合并或不再单独输出，具体要看版本。

### 4. dfl_loss

DFL 是 Distribution Focal Loss。

普通框回归直接预测一个连续值，例如：

```text
left = 7.3
```

DFL 会把距离建模成离散分布：

```text
left 属于 0, 1, 2, ..., reg_max 的概率分布
```

最后通过期望得到连续距离。

作用：

- 提升边界框定位精度；
- 让模型表达不确定性；
- 常和 anchor-free 的 l/t/r/b 距离预测一起使用。

## 九、IoU 相关名词

### 1. IoU

IoU 表示预测框和真实框的重叠程度：

```text
IoU = 交集面积 / 并集面积
```

IoU 取值范围：

```text
0 到 1
```

越接近 1，框越准。

### 2. GIoU

GIoU 解决普通 IoU 在两个框不重叠时没有梯度方向的问题。

它会考虑包围两个框的最小外接框。

### 3. DIoU

DIoU 在 IoU 基础上加入中心点距离。

如果两个框 IoU 一样，中心点更近的框更好。

### 4. CIoU

CIoU 同时考虑：

- 重叠面积；
- 中心点距离；
- 宽高比一致性。

YOLOv4、YOLOv5 等版本中经常看到 CIoU。

## 十、DFL、Reg-Max 和边界框分布

现代 YOLO 中常见：

```text
reg_max = 16
```

它表示每条边的距离不是直接预测一个数，而是预测 `0 到 reg_max` 的离散分布。

例如每个点预测四条边：

```text
left, top, right, bottom
```

如果 `reg_max=16`，每条边输出 16 或 17 个分布值，具体取决于实现。

最终通过 integral 操作得到连续距离：

```text
distance = Σ(prob_i * i)
```

优点是边界框定位更细腻，缺点是输出通道和计算会增加。

## 十一、Confidence、Objectness、Class Score

这几个词容易混淆。

### 1. Objectness

objectness 表示当前预测位置是否有目标。

它回答的是：

```text
这里有没有物体？
```

不是：

```text
这里是什么类别？
```

### 2. Class Score

class score 表示类别概率。

它回答的是：

```text
如果这里有物体，它属于哪个类别？
```

### 3. Confidence

confidence 在不同文章里用法不完全一致。

在很多 YOLO 版本中，最终框分数是：

```text
confidence = objectness * class_score
```

在一些现代 YOLO 中，objectness 可能没有单独分支，最终 score 可能直接来自分类质量或任务对齐分数。

## 十二、解耦头 Decoupled Head

早期 YOLO 检测头常把分类、定位、objectness 混在同一组卷积输出里。

解耦头会把分类和回归分成不同分支：

```text
Feature
  -> cls branch -> class score
  -> reg branch -> bbox
```

有些版本还会有 objectness branch。

优点：

- 分类和定位任务关注点不同；
- 分开学习更稳定；
- 方便配合 TAL、DFL 等现代机制。

YOLOX、YOLOv6、YOLOv8 等都常见解耦头思想。

## 十三、NMS 和 NMS-Free

### 1. NMS

NMS 是 Non-Maximum Suppression，非极大值抑制。

推理阶段模型会产生很多重复框，NMS 用于去重：

```text
按 score 排序
  -> 取最高分框
  -> 删除与它 IoU 过高的同类框
  -> 继续处理剩余框
```

常见参数：

| 参数 | 说明 |
|---|---|
| conf_thres | 置信度阈值 |
| iou_thres | NMS IoU 阈值 |
| max_det | 最多保留多少个检测框 |

### 2. Soft-NMS

Soft-NMS 不直接删除重叠框，而是降低它们的分数。

适合密集目标场景，但计算和实现略复杂。

### 3. DIoU-NMS

DIoU-NMS 在判断重复框时，不只看 IoU，也考虑中心点距离。

### 4. NMS-Free

NMS-free 目标是减少或去掉传统 NMS 后处理。

思路通常包括：

- 一对一标签分配；
- 去重训练策略；
- 端到端检测头；
- 让模型直接输出较少的高质量框。

YOLOv10 强调 NMS-free 方向。

需要注意：NMS-free 不等于训练时没有标签分配，也不等于完全没有筛选逻辑。它的核心是减少传统贪心 NMS 对推理结果和速度的影响。

## 十四、mAP、Precision、Recall

训练目标检测模型时，不能只看 loss，还要看检测指标。

### 1. Precision

Precision 表示预测出来的框有多少是真的。

```text
Precision = TP / (TP + FP)
```

Precision 高，说明误检少。

### 2. Recall

Recall 表示真实目标有多少被找到了。

```text
Recall = TP / (TP + FN)
```

Recall 高，说明漏检少。

### 3. AP

AP 是 Average Precision，即单个类别的 PR 曲线下面积。

### 4. mAP

mAP 是 mean Average Precision，对多个类别 AP 求平均。

常见写法：

| 指标 | 说明 |
|---|---|
| mAP@0.5 | IoU 阈值为 0.5 时的 mAP |
| mAP@0.5:0.95 | IoU 从 0.5 到 0.95 多个阈值平均，更严格 |

`mAP@0.5:0.95` 比 `mAP@0.5` 更能反映定位精度。

## 十五、训练日志怎么看

训练日志常见字段：

```text
box_loss
cls_loss
obj_loss
dfl_loss
precision
recall
mAP50
mAP50-95
lr
```

### 1. loss 下降但 mAP 不涨

可能原因：

- 数据标注有问题；
- 类别 id 配置错误；
- 验证集分布和训练集差异大；
- 学习率不合适；
- 过拟合；
- NMS/conf 阈值影响评估。

### 2. box_loss 高

可能原因：

- 标注框不准；
- 小目标太多；
- 输入尺寸太小；
- anchor 不适配，针对 anchor-based；
- 数据增强过强。

### 3. cls_loss 高

可能原因：

- 类别太相似；
- 类别标注错误；
- 类别不均衡；
- 训练数据太少。

### 4. obj_loss 高

常见于 anchor-based 旧版 YOLO。

可能原因：

- 正负样本比例失衡；
- 背景复杂；
- anchor 匹配不合理；
- ignore 阈值设置不合适。

### 5. dfl_loss 高

常见于现代 YOLO。

可能原因：

- 边界框标注质量差；
- 小目标定位难；
- 输入尺寸不足；
- reg_max 或分配策略不适合当前任务。

## 十八、版本演进中的训练机制主线

可以按下面这条线理解 YOLO 训练机制的演进：

```text
YOLOv1:
  grid cell 直接回归框

YOLOv2-v3:
  anchor-based
  anchor 与 GT 匹配
  objectness + class + bbox loss

YOLOv4-v5:
  anchor-based 继续强化
  Mosaic、CIoU、AutoAnchor、PAN 等工程增强

YOLOX / YOLOv6 / YOLOv8:
  anchor-free 趋势增强
  decoupled head
  dynamic label assignment
  DFL / TAL 等现代机制

YOLOv10 以后:
  NMS-free / end-to-end 检测方向增强
```

核心变化是：

```text
从固定规则分配
  -> 到动态标签分配
从 anchor box 先验
  -> 到 anchor-free 点预测
从简单坐标回归
  -> 到 IoU Loss + DFL 分布回归
从强依赖 NMS
  -> 到减少 NMS 或 NMS-free
```

学习 YOLO 训练时，建议先掌握四个问题：

1. 一个 GT 到底分配给哪些预测位置？
2. 哪些位置算正样本、负样本、ignore 样本？
3. 每种样本分别参与哪些 loss？
4. 推理时预测框如何解码和去重？

这四个问题理解清楚后，再看不同版本的 YOLO 训练代码会容易很多。
