# 大模型微调面试题 200 道

本文整理大模型微调相关面试题与参考答案，覆盖 SFT、数据构造、Chat Template、Label Mask、LoRA/QLoRA、DPO/PPO/RLHF、训练参数、显存优化、分布式训练、评估、部署和常见排障。

## 一、微调基础

### 1. 大模型微调是什么？

微调是在预训练模型基础上，用特定任务或领域数据继续训练，让模型适应新的指令格式、知识领域、输出风格或业务目标。

### 2. 预训练和微调有什么区别？

预训练使用海量通用语料学习语言和世界知识；微调使用更小、更有目标的数据，让模型学会特定任务、格式和偏好。

### 3. 为什么需要微调？

因为预训练模型不一定符合具体业务要求。微调可以提升指令跟随、领域表达、格式稳定性、安全边界和任务准确率。

### 4. 微调能让模型学会新知识吗？

可以在一定程度上记住领域知识，但微调更适合学习行为和格式。频繁变化、规模很大的知识通常更适合 RAG 或工具检索。

### 5. SFT 是什么？

SFT 是 Supervised Fine-Tuning，监督微调。它用 prompt-answer 或多轮对话数据训练模型模仿标准答案。

### 6. Instruction Tuning 是什么？

Instruction Tuning 是用指令数据微调模型，让模型学会理解和执行自然语言指令，是 SFT 的重要形式。

### 7. 微调和 Prompt Engineering 有什么区别？

Prompt Engineering 不改模型参数，只通过输入提示控制行为；微调会更新参数或 adapter，让行为固化到模型中。

### 8. 什么场景适合微调？

适合输出格式稳定、领域风格明确、任务边界清晰、需要批量降低 prompt 成本、或基础模型指令跟随不满足业务要求的场景。

### 9. 什么场景不适合微调？

知识频繁变化、问题需要实时数据库、样本很少且质量差、业务规则经常变、或只需简单提示即可解决时，不应优先微调。

### 10. 微调的常见阶段有哪些？

常见阶段是 SFT、偏好优化 DPO/RLHF、评估、合并或导出权重、推理部署和线上反馈迭代。

## 二、数据构造与质量

### 11. 微调数据为什么重要？

微调数据直接决定模型学到什么行为。低质量数据会导致格式错误、幻觉、语气异常、拒答边界混乱和灾难性遗忘。

### 12. SFT 数据常见格式是什么？

常见格式包括 `instruction + input + output`、`prompt + response`、以及多轮 `messages` 列表格式。

### 13. 多轮对话数据通常如何表示？

通常用 `messages` 数组表示，每条消息包含 `role` 和 `content`，role 常见为 system、user、assistant、tool。

### 14. 为什么要保证训练格式和推理格式一致？

模型学习的是 token 序列模式。如果训练时 chat template 和推理时不同，模型可能无法识别角色边界和回答位置，效果会明显下降。

### 15. Chat Template 是什么？

Chat Template 是把结构化多轮消息转换成模型实际输入文本的模板，包含角色标记、换行、特殊 token 和 assistant 起始标记。

### 16. 数据清洗通常包括什么？

包括去重、去乱码、过滤低质量样本、统一格式、删除泄漏字段、处理超长样本、检查标签为空和清理敏感内容。

### 17. 为什么要去重？

重复样本会让模型过拟合某些表达，浪费训练步数，并可能导致评估集泄漏，使指标虚高。

### 18. 训练集和评估集如何划分？

应按任务、来源、用户或时间合理划分，避免同一问题或近似样本同时出现在训练和评估集中。

### 19. 数据量越多越好吗？

不一定。高质量、小规模、目标明确的数据常比大量噪声数据更有效。数据质量和覆盖面比单纯数量更重要。

### 20. 如何判断一条 SFT 样本质量高？

prompt 清晰，answer 正确、有帮助、格式稳定，和业务目标一致，没有无意义套话、幻觉、敏感泄漏或明显模板污染。

## 三、Tokenization 与 Label Mask

### 21. 微调前为什么要检查 tokenizer？

Tokenizer 决定文本如何切成 token。若 tokenizer 与模型不匹配，输入 id 错误，模型训练和推理都会异常。

### 22. 什么是 max_seq_length？

max_seq_length 是训练样本 token 化后的最大长度。超过长度通常会截断，过短会丢信息，过长会增加显存和训练时间。

### 23. 截断样本有什么风险？

可能截掉回答、关键上下文、结束 token 或角色边界，导致模型学习错误格式或 loss 异常。

### 24. Padding 有什么作用？

Padding 把同一个 batch 内不同长度样本补齐，便于张量并行计算。需要 attention mask 防止模型关注 pad token。

### 25. Attention mask 在训练中有什么作用？

它告诉模型哪些 token 是有效输入，哪些是 padding，避免无效位置参与 attention。

### 26. Labels 是什么？

Labels 是语言模型训练的目标 token。Causal LM 中通常把输入右移一位，让模型预测下一个 token。

### 27. Label Mask 是什么？

Label Mask 是把不需要计算 loss 的位置设为 `-100`，例如 user prompt、system prompt 和 padding，只让 assistant answer 参与 loss。

### 28. 为什么 SFT 通常只训练 assistant 部分？

因为目标是让模型学会回答，而不是复述用户问题或 system prompt。只对 assistant 计算 loss 可以让训练目标更清晰。

### 29. 如果 label mask 写错会怎样？

模型可能学会复述 prompt、角色标记混乱、loss 异常低或不下降、回答格式错，甚至推理时无法正常停下。

### 30. 如何检查 label mask 是否正确？

把 token decode 回文本，并标出哪些 token 参与 loss。确认只有目标回答部分有标签，prompt、pad 和无关字段被 mask。

## 四、SFT 训练目标

### 31. Causal LM 微调的核心目标是什么？

给定前文 token，预测下一个 token。SFT 通过交叉熵让模型在回答位置更倾向标准答案。

### 32. Teacher Forcing 是什么？

训练时每一步都使用真实历史 token 作为输入，而不是模型自己生成的 token。这样训练更稳定且可并行。

### 33. SFT loss 是怎么计算的？

模型输出每个位置的 logits，与 labels 中未被 mask 的目标 token 计算交叉熵，然后对有效 token 求平均。

### 34. 为什么 loss 很低但实际效果可能不好？

可能评估集泄漏、回答模板简单、label mask 错误、数据分布过窄，或 loss 只反映 token 拟合，不等于真实任务质量。

### 35. 为什么 loss 不下降？

常见原因是学习率不合适、数据格式错、labels 全是 `-100`、训练参数没解冻、target modules 错、显存溢出导致训练异常。

### 36. 为什么 loss 下降但模型变笨？

可能是数据质量差、领域过窄、训练过度、学习率太大或遗忘通用能力。需要评估通用能力和业务能力的权衡。

### 37. 什么是过拟合？

模型过度记住训练集，训练 loss 下降但验证集和真实场景表现变差。小数据高 epoch 微调容易过拟合。

### 38. 如何缓解微调过拟合？

提高数据质量、减少 epoch、降低学习率、使用 dropout、扩大验证集、早停、减小 LoRA rank 或增加数据多样性。

### 39. 什么是灾难性遗忘？

模型在新任务数据上训练后，原有通用能力下降。例如微调客服话术后数学、代码或常识能力明显变差。

### 40. 如何缓解灾难性遗忘？

使用 LoRA、降低学习率、混入通用指令数据、减少训练步数、做多任务数据混合，并保留参考评测集。

## 五、训练参数

### 41. learning rate 对微调有什么影响？

学习率决定参数更新幅度。太大容易发散或遗忘，太小训练慢或学不到任务。LoRA 通常可用比全量微调更大的学习率。

### 42. LoRA 微调常见学习率范围是多少？

常见从 `1e-5` 到 `3e-4`，具体取决于数据规模、rank、模型大小和任务难度。

### 43. 全量微调学习率为什么通常更小？

全量微调更新所有参数，影响模型整体能力，学习率过大容易破坏预训练权重，因此通常比 LoRA 小。

### 44. batch size 有什么作用？

batch size 决定每次更新使用多少样本。较大 batch 梯度更稳定但显存更高，较小 batch 噪声更大但更省显存。

### 45. gradient_accumulation_steps 是什么？

梯度累积是在多个小 batch 上累积梯度后再更新一次参数，用较小显存模拟更大的有效 batch。

### 46. global batch size 如何计算？

`global_batch_size = per_device_train_batch_size * GPU 数量 * gradient_accumulation_steps`。

### 47. epoch 是什么？

epoch 表示完整遍历训练集一次。小数据集 epoch 太多容易过拟合，大数据集可能只需少量 epoch。

### 48. warmup 的作用是什么？

Warmup 在训练初期逐步升高学习率，避免刚开始梯度不稳定时直接大步更新导致发散。

### 49. weight decay 在微调中有什么作用？

Weight decay 是正则化手段，限制权重过大。LoRA 微调中常设置较小，bias 和 norm 参数通常不做 weight decay。

### 50. gradient clipping 有什么作用？

它限制梯度范数，防止梯度爆炸，提升训练稳定性。

## 六、LoRA

### 51. LoRA 是什么？

LoRA 是 Low-Rank Adaptation，冻结原模型权重，在部分线性层旁加入低秩可训练矩阵，只训练这些增量参数。

### 52. LoRA 的核心公式是什么？

对线性层权重 `W`，LoRA 学习低秩增量 `ΔW = BA`，实际输出是 `xW + xBA * alpha/r`。

### 53. LoRA 为什么省显存？

它只训练少量 adapter 参数，不需要为全部模型参数保存梯度和优化器状态，因此显存和保存成本大幅降低。

### 54. LoRA 的 r 表示什么？

`r` 是低秩矩阵 rank，控制 adapter 表达能力和参数量。r 越大，能力越强但显存、训练成本和过拟合风险越高。

### 55. lora_alpha 是什么？

lora_alpha 是缩放系数，实际缩放通常是 `alpha/r`，控制 LoRA 增量对原始输出的影响强度。

### 56. lora_dropout 有什么作用？

lora_dropout 在 LoRA 分支上做 dropout，缓解小数据过拟合。数据很大时可设为 0 或较小值。

### 57. target_modules 是什么？

target_modules 指定在哪些线性层插入 LoRA，例如 `q_proj`、`v_proj`、`o_proj`、`gate_proj`、`up_proj`、`down_proj`。

### 58. LoRA 通常加在哪些层？

常见加在 attention 的 Q/V 或 Q/K/V/O，也可加在 MLP 的 gate/up/down 投影。覆盖越多，表达更强但成本更高。

### 59. 为什么有些训练不微调 lm_head？

lm_head 参数量大，训练它会增加显存和保存成本。多数指令微调只训练 Transformer 内部线性层即可。

### 60. LoRA adapter 可以合并吗？

可以。推理时可把 LoRA 增量合并进原始权重，减少 adapter 分支开销，得到普通模型权重。

## 七、QLoRA 与量化微调

### 61. QLoRA 是什么？

QLoRA 是把基座模型以 4bit 量化加载并冻结，只训练 LoRA adapter 的参数高效微调方法。

### 62. QLoRA 和 LoRA 的区别是什么？

LoRA 通常在 FP16/BF16 基座上训练 adapter；QLoRA 基座是 4bit 量化加载，更省显存，但环境和数值细节更复杂。

### 63. QLoRA 为什么省显存？

最大部分的基座权重以 4bit 存储，只有 LoRA adapter、少量状态和激活使用较高精度，因此显存占用显著降低。

### 64. NF4 是什么？

NF4 是 NormalFloat4，一种适合近似正态分布权重的 4bit 数据格式，QLoRA 中常用。

### 65. Double Quantization 是什么？

Double Quantization 是对量化 scale 再量化，进一步减少量化元数据显存。

### 66. paged optimizer 是什么？

Paged optimizer 用分页方式管理优化器状态，减少显存峰值，QLoRA 常用 `paged_adamw_8bit`。

### 67. prepare_model_for_kbit_training 有什么作用？

它会为 k-bit 训练做准备，例如处理 norm 精度、开启输入梯度、禁用 cache 等，使量化模型可稳定训练 LoRA。

### 68. QLoRA 合并权重时要注意什么？

通常不要直接在 4bit 权重上粗暴合并。应加载非量化基座，再加载 adapter 进行 merge，避免精度和格式问题。

### 69. QLoRA 训练为什么可能比 LoRA 慢？

因为存在量化权重的反量化计算和 bitsandbytes kernel 开销，虽然显存省，但速度不一定更快。

### 70. QLoRA 常见环境问题有哪些？

bitsandbytes、CUDA、GPU 架构、transformers、peft、accelerate 版本不匹配，可能导致 4bit 加载失败或训练报错。

## 八、全量微调与 PEFT

### 71. 全量微调是什么？

全量微调更新模型所有或绝大多数参数，能力上限高，但显存、训练成本和保存成本很高。

### 72. PEFT 是什么？

PEFT 是 Parameter-Efficient Fine-Tuning，参数高效微调，只训练少量新增或选择性参数，例如 LoRA、Adapter、Prefix Tuning。

### 73. 全量微调和 LoRA 如何选择？

数据量大、资源充足、任务强改造可考虑全量；资源有限、多任务切换、快速实验和领域适配通常优先 LoRA。

### 74. Adapter Tuning 是什么？

Adapter Tuning 在 Transformer 层中插入小型网络，只训练 adapter。它会增加推理路径，和 LoRA 的权重增量方式不同。

### 75. Prefix Tuning 是什么？

Prefix Tuning 学习一组可训练 prefix 向量，让模型在不改主体参数的情况下适配任务。

### 76. Prompt Tuning 是什么？

Prompt Tuning 学习连续软 prompt embedding，而不是人工写离散 prompt，通常只训练少量 prompt 参数。

### 77. BitFit 是什么？

BitFit 只训练 bias 参数，是一种极轻量微调方法，但能力有限。

### 78. IA3 是什么？

IA3 通过训练缩放向量调节 attention 和 FFN 激活，是一种参数量很小的 PEFT 方法。

### 79. PEFT 的主要优点是什么？

显存低、训练快、保存小、便于多任务 adapter 管理，并能降低灾难性遗忘风险。

### 80. PEFT 的主要缺点是什么？

表达能力受限，对 target modules、rank 和数据质量敏感，在强领域迁移任务上可能不如全量微调。

## 九、DPO 与偏好优化

### 81. DPO 是什么？

DPO 是 Direct Preference Optimization，使用 prompt、chosen、rejected 偏好对训练模型，让模型更偏向 chosen，远离 rejected。

### 82. DPO 数据格式是什么？

通常包含 `prompt`、`chosen`、`rejected`。chosen 是更好的回答，rejected 是较差回答。

### 83. DPO 和 SFT 的区别是什么？

SFT 模仿单个标准答案；DPO 学习两个回答之间的偏好差异，更适合优化风格、安全性和人类偏好。

### 84. DPO 为什么不需要 Reward Model？

DPO 直接从偏好对构造损失，把奖励建模和策略优化合并到一个监督式目标中，因此不需要单独训练奖励模型。

### 85. DPO 中 reference model 的作用是什么？

Reference model 提供基准分布，限制 policy model 不要过度偏离 SFT 模型，保持语言质量和稳定性。

### 86. DPO 的 beta 参数如何理解？

beta 控制 policy 偏离 reference 的强度。beta 大约束更强，模型更保守；beta 小偏好学习更激进，但更可能跑偏。

### 87. DPO 为什么显存比 SFT 高？

DPO 要处理 chosen 和 rejected，并通常需要 policy 和 reference 的 logprob，计算图和输入长度都比 SFT 更重。

### 88. DPO 后模型回答变短可能是什么原因？

偏好数据中 chosen 普遍更短、长度偏好未控制、beta 不合适或评估方式偏向短答案，模型会学到长度偏差。

### 89. DPO 数据构造最重要的是什么？

chosen 必须真实优于 rejected，差异要清晰、有代表性，不能只是长度不同或模板不同。

### 90. DPO 是否一定要在 SFT 后做？

通常建议在 SFT 后做。SFT 先建立基本指令跟随和格式能力，DPO 再做偏好对齐更稳定。

## 十、RLHF 与 PPO

### 91. RLHF 是什么？

RLHF 是 Reinforcement Learning from Human Feedback，用人类反馈训练奖励模型，再用强化学习优化语言模型行为。

### 92. RLHF 典型流程是什么？

典型流程是 SFT、收集偏好数据、训练 Reward Model、使用 PPO 等算法优化 policy model，最后评估和安全对齐。

### 93. PPO 在大模型微调中做什么？

PPO 让模型生成能获得更高奖励的回答，同时通过 KL 约束防止模型偏离 reference model 太远。

### 94. PPO 中有哪些模型？

通常包括 Policy Model、Reference Model、Reward Model 和 Value/Critic Model。

### 95. Reward Model 是什么？

Reward Model 输入 prompt 和 response，输出一个奖励分数，用于评价回答质量或偏好。

### 96. KL penalty 的作用是什么？

KL penalty 限制当前 policy 与 reference model 的差异，防止模型为了追求 reward 破坏语言质量或安全性。

### 97. Reward Hacking 是什么？

Reward Hacking 是模型钻奖励函数漏洞，生成看似高分但实际质量差的回答。

### 98. PPO 和 DPO 最大区别是什么？

DPO 不需要奖励模型和在线采样，工程更简单；PPO 通常需要 reward/value/reference 多模型和 rollout，复杂度更高。

### 99. PPO 为什么难调？

它涉及采样策略、reward scale、KL 系数、value loss、clip range、batch、生成长度等多个敏感超参。

### 100. 什么场景更适合 PPO？

当有明确奖励函数、需要在线探索、偏好目标复杂或希望直接优化任务指标时，可以考虑 PPO。

## 十一、训练显存优化

### 101. 微调显存主要花在哪里？

主要包括模型权重、梯度、优化器状态、激活值、临时 buffer 和 batch 数据。全量微调还要保存所有参数的梯度和 optimizer state。

### 102. 为什么 AdamW 显存占用高？

AdamW 需要为每个可训练参数保存一阶和二阶动量状态，通常比参数本身占用更多显存。

### 103. gradient checkpointing 是什么？

它不保存部分前向激活，反向传播时重新计算，用计算时间换显存。

### 104. gradient checkpointing 的代价是什么？

训练会变慢，因为反向时需要重新计算部分前向过程，但显存峰值会下降。

### 105. 混合精度训练有什么作用？

FP16/BF16 能减少显存和加速矩阵计算。BF16 指数范围更大，通常比 FP16 更稳定。

### 106. FP16 和 BF16 如何选择？

支持 BF16 的硬件上优先 BF16；老硬件只能 FP16 时，可能需要 loss scaling 处理数值稳定。

### 107. 为什么训练时要关闭 use_cache？

`use_cache` 用于推理 KV Cache。训练反向传播不需要它，开启会增加显存且可能与 gradient checkpointing 冲突。

### 108. 如何降低微调显存？

可使用 LoRA/QLoRA、减小 batch、缩短 seq length、开启 gradient checkpointing、使用 ZeRO/FSDP、混合精度和 8bit optimizer。

### 109. 8bit optimizer 有什么作用？

它用低精度保存优化器状态，降低显存占用，常用于显存紧张的 LoRA/QLoRA 微调。

### 110. 为什么 seq length 对显存影响很大？

Transformer 激活和 attention 与序列长度强相关，长度越长，训练显存和计算时间都显著增加。

## 十二、分布式训练

### 111. Data Parallel 是什么？

Data Parallel 每张 GPU 放一份完整模型，处理不同 batch 数据，再同步梯度。

### 112. DDP 是什么？

DDP 是 PyTorch 的 DistributedDataParallel，多进程多 GPU 训练，每个进程持有模型副本，通过通信同步梯度，效率通常优于 DataParallel。

### 113. DP 和 DDP 有什么区别？

DP 是单进程控制多卡，开销较大；DDP 是多进程多卡，每卡独立进程，通信和扩展性更好。

### 114. ZeRO 是什么？

ZeRO 是 DeepSpeed 的显存优化技术，把优化器状态、梯度和参数切分到多卡，降低单卡显存。

### 115. ZeRO-1、ZeRO-2、ZeRO-3 区别是什么？

ZeRO-1 切 optimizer states；ZeRO-2 切 optimizer states 和 gradients；ZeRO-3 进一步切 parameters，最省显存但通信和保存更复杂。

### 116. FSDP 是什么？

FSDP 是 Fully Sharded Data Parallel，把参数、梯度和优化器状态分片，在计算时按需聚合，类似 ZeRO-3 思路。

### 117. Tensor Parallel 是什么？

Tensor Parallel 把模型单层矩阵计算切分到多张 GPU 上，适合单卡放不下的大模型。

### 118. Pipeline Parallel 是什么？

Pipeline Parallel 把模型不同层放到不同 GPU 上，用 micro-batch 流水线执行，适合非常深的大模型。

### 119. Accelerate 和 DeepSpeed 的关系是什么？

Accelerate 是训练封装和调度层，可统一管理 DDP、FSDP、DeepSpeed；DeepSpeed 是具体高性能训练引擎。

### 120. LoRA 结合 ZeRO-3 有什么注意点？

需要确认只训练 adapter、保存时正确 gather 权重、避免误保存分片参数，并处理 PEFT/DeepSpeed 版本兼容。

## 十三、数据 Collator 与训练工程

### 121. Data Collator 是什么？

Data Collator 负责把样本组成 batch，包括 padding、生成 attention mask、labels 和必要的格式转换。

### 122. 微调中 Data Collator 最容易出什么问题？

常见问题是 padding 错、labels mask 错、样本截断错、不同字段拼接错、EOS 缺失和 batch 维度不一致。

### 123. packing 是什么？

Packing 是把多个短样本拼接到一个长序列中，提高 token 利用率，减少 padding 浪费。

### 124. packing 有什么风险？

如果 attention mask 或 labels 处理不对，模型可能把两个无关样本当作连续上下文学习。

### 125. EOS token 为什么重要？

EOS 告诉模型回答结束。训练数据缺 EOS 可能导致推理时模型不容易停止。

### 126. PAD token 如何设置？

许多 decoder-only 模型没有原生 pad token，常把 pad token 设置为 eos token，但必须配合 attention mask 和 labels mask。

### 127. 为什么要保存训练配置？

训练配置决定可复现性，包括模型版本、数据版本、学习率、batch、LoRA 参数、seed 和依赖版本。

### 128. seed 有什么作用？

seed 控制随机初始化、数据 shuffle、dropout 等随机性，帮助复现实验，但分布式和 GPU 算子仍可能有小差异。

### 129. checkpoint 保存什么？

可能保存模型权重、adapter、optimizer state、scheduler state、训练步数和随机状态。LoRA 常只保存 adapter。

### 130. resume training 要注意什么？

要恢复模型、optimizer、scheduler、global step、数据进度和随机状态，否则学习率和训练进度可能不一致。

## 十四、评估与验证

### 131. 微调后如何评估？

应结合自动指标、业务测试集、人工评估、对比评测、回归测试和线上 A/B，而不是只看训练 loss。

### 132. SFT 常见自动指标有哪些？

可用 loss、perplexity、准确率、F1、BLEU/ROUGE、格式通过率、工具调用成功率等，取决于任务类型。

### 133. 为什么大模型评估需要人工检查？

很多回答质量、事实性、语气、安全性和业务合规无法被简单自动指标完全覆盖。

### 134. 如何评估格式遵循能力？

构造格式测试集，检查 JSON/XML/SQL/函数调用是否可解析、字段是否完整、类型是否正确。

### 135. 如何评估微调是否遗忘通用能力？

保留通用问答、数学、代码、常识和安全测试集，与基座模型和 SFT 前模型对比。

### 136. 如何评估 DPO 效果？

比较 chosen/rejected 偏好胜率、人工偏好、回答长度、拒答边界、安全性和业务指标，避免只看 DPO loss。

### 137. 如何评估过拟合？

观察训练集和验证集 loss 差距，检查模型是否复述训练样本，在未见问题上是否泛化。

### 138. 为什么要做 baseline？

Baseline 提供对照，能判断微调是否真正带来收益，而不是模型本身或 prompt 改动带来的效果。

### 139. A/B 测试在微调中有什么作用？

A/B 测试能在真实流量中比较基座模型、旧模型和新模型的业务指标、用户满意度和错误率。

### 140. 微调评估最常见误区是什么？

只看 loss 或少量样例，不看真实分布、长尾问题、安全边界、格式稳定性和通用能力回退。

## 十五、部署与推理

### 141. LoRA adapter 如何部署？

可以运行时加载 base model + adapter，也可以把 adapter merge 到 base model 后部署成普通权重。

### 142. merge LoRA 的优点是什么？

推理链路更简单，不需要额外 adapter 分支，兼容更多推理框架，延迟可能更低。

### 143. 不 merge LoRA 的优点是什么？

可动态切换多个 adapter，节省存储，适合多租户、多任务或 A/B 测试。

### 144. 多 LoRA 服务是什么？

同一个基座模型加载多个 LoRA adapter，根据请求选择不同 adapter，减少多模型副本的显存成本。

### 145. LoRA merge 后还能继续训练 adapter 吗？

可以重新基于合并后的权重训练新 adapter，但原 adapter 的独立性会丢失。通常保留原始 adapter 文件更灵活。

### 146. 微调模型部署时最容易出什么错？

tokenizer 不一致、chat template 不一致、adapter 没加载、特殊 token 错、量化格式不兼容或 max length 配置不同。

### 147. 为什么训练效果好但部署效果差？

常见是推理 prompt 格式和训练不一致、解码参数不同、adapter 未加载、模型版本错或线上输入分布不同。

### 148. 微调后需要调整解码参数吗？

可能需要。temperature、top_p、max_new_tokens、repetition_penalty 会影响输出风格和稳定性，应与业务目标一起调。

### 149. 微调模型如何做版本管理？

记录 base model、adapter、数据版本、训练配置、评估报告、依赖版本和部署参数，确保可回滚。

### 150. 微调和 RAG 可以结合吗？

可以。微调用于学习格式和行为，RAG 用于提供实时知识，两者结合通常比单独微调知识更稳。

## 十六、常见故障排查

### 151. LoRA 微调效果不好怎么排查？

先检查数据 decode 和 label mask，再检查 chat template、target_modules、学习率、训练步数、rank、数据质量和推理格式。

### 152. 模型微调后只会复读怎么办？

可能 labels 包含 prompt、数据重复严重、学习率过高、训练过拟合或 EOS 缺失。应检查 label mask 和样本多样性。

### 153. 模型微调后不会停止怎么办？

可能训练数据缺 EOS、推理 stop token 配置错、chat template 不匹配或 max_new_tokens 设置过大。

### 154. 训练中 loss 变成 NaN 怎么办？

检查学习率、FP16 溢出、梯度裁剪、数据异常、序列过长、量化配置和是否使用 BF16。

### 155. CUDA OOM 怎么处理？

减小 batch、缩短 seq length、开启 gradient checkpointing、使用 LoRA/QLoRA、ZeRO/FSDP、8bit optimizer 或更小模型。

### 156. 训练很慢怎么排查？

看数据加载、tokenization 是否在线执行、GPU 利用率、batch size、gradient checkpointing、通信开销、存储 IO 和日志保存频率。

### 157. 多卡训练卡住可能是什么原因？

可能是 NCCL 通信问题、某个进程 OOM、数据长度不一致、barrier 死锁、网络问题或分布式环境变量错误。

### 158. 模型输出乱码可能是什么原因？

tokenizer 不匹配、权重加载错、adapter 不匹配、量化损坏、特殊 token 错或 chat template 错。

### 159. 训练后模型拒答变多怎么办？

可能安全拒答数据比例过高、DPO 偏好过强、beta 不合适或 prompt 分布偏差。需要平衡数据和调整偏好优化参数。

### 160. 微调后幻觉增加怎么办？

提高数据事实性、减少编造样本、加入“不知道”样本、结合 RAG、降低学习率，并用事实性评估集回归测试。

## 十七、领域微调与业务落地

### 161. 领域微调的目标是什么？

让模型适应特定行业术语、回答风格、任务流程和输出格式，而不是简单灌入全部领域知识。

### 162. 医疗、法律等高风险领域微调要注意什么？

需要高质量专家数据、合规审查、安全边界、不可替代专业判断的声明、严格评估和可追溯版本管理。

### 163. 客服场景微调重点是什么？

重点是语气一致、流程遵循、知识调用、拒答边界、工单格式和多轮对话稳定性。

### 164. 代码模型微调重点是什么？

重点是代码正确性、测试通过率、依赖版本、指令格式、长上下文文件理解和安全限制。

### 165. 工具调用微调数据如何构造？

需要包含用户请求、工具 schema、模型选择工具的过程、工具参数、工具返回结果和最终回答。

### 166. Function Calling 微调最重要的是什么？

确保 JSON 参数合法、字段完整、类型正确、工具选择准确，并训练模型不要编造不存在的工具。

### 167. 结构化输出微调如何做？

构造严格格式样本，训练时只让目标结构参与 loss，评估时用解析器验证合法性，而不是只看文本相似度。

### 168. 小样本微调有什么风险？

容易过拟合、风格偏移、遗忘通用能力，并且对学习率、epoch、rank 和数据质量非常敏感。

### 169. 数据混合比例如何确定？

根据业务目标平衡领域数据、通用指令、安全数据和格式数据。需要通过验证集和消融实验调比例。

### 170. 如何避免模型学到错误业务规则？

数据要经过业务审核，规则变化要版本化，训练集要去除过期样本，关键规则最好结合检索或工具而不是只靠参数记忆。

## 十八、训练策略与实验设计

### 171. 微调实验如何设计？

固定 base model 和评估集，从小数据、小步数开始，逐步调整学习率、rank、target_modules、seq length 和数据比例。

### 172. 为什么要做小规模 sanity check？

小规模训练能快速发现数据格式、label mask、loss、保存加载和推理链路问题，避免浪费大规模训练成本。

### 173. 什么是 overfit small batch 测试？

用极少量样本训练，看模型能否快速记住。如果不能，说明训练链路、labels 或参数解冻可能有问题。

### 174. 如何做消融实验？

一次只改变一个变量，例如学习率、rank、target modules、数据来源或 epoch，观察评估指标变化。

### 175. 训练日志应记录什么？

记录 train/eval loss、learning rate、grad norm、吞吐、显存、step time、样例输出和保存 checkpoint 信息。

### 176. eval_steps 和 save_steps 如何设置？

小实验可频繁评估保存，大训练应结合数据规模和成本设置，避免评估过密拖慢训练或 checkpoint 过多占磁盘。

### 177. early stopping 有什么作用？

当验证指标不再提升时提前停止训练，减少过拟合和训练成本。

### 178. 为什么要固定评估 prompt？

固定评估 prompt 能可比地观察不同 checkpoint 的行为变化，尤其是格式、语气和边界能力。

### 179. 如何选择最佳 checkpoint？

综合验证 loss、业务指标、人工评估和安全回归，不一定选择训练 loss 最低的 checkpoint。

### 180. 微调实验最重要的原则是什么？

可复现、可对比、一次只改关键变量，并用真实业务评估集判断收益。

## 十九、模型对齐与安全

### 181. 对齐微调是什么？

对齐微调是让模型输出更符合人类偏好、安全规范、价值边界和业务要求，常通过 SFT、DPO、RLHF 完成。

### 182. 安全数据在微调中有什么作用？

安全数据训练模型识别危险请求、隐私信息和违规内容，并给出合适拒答或安全替代建议。

### 183. 过度拒答是什么？

模型对正常请求也拒绝回答，通常由安全数据比例过高、拒答模板单一或偏好优化过强导致。

### 184. 如何降低过度拒答？

加入安全可回答样本、区分危险与正常边界、优化拒答模板比例，并做细粒度安全评估。

### 185. DPO 会不会损害安全性？

可能。如果偏好数据质量差或 chosen/rejected 标注不当，DPO 可能强化错误边界。因此需要安全回归测试。

### 186. Reward Model 质量差会怎样？

PPO 会优化错误奖励，导致 reward hacking、语言质量下降、安全边界破坏或输出模式异常。

### 187. 微调数据中有隐私信息怎么办？

应在训练前脱敏、删除或合规处理。不要让模型记忆个人隐私、密钥、内部凭证或敏感业务数据。

### 188. 如何检测模型是否记忆训练样本？

用训练样本近似 prompt 测试模型是否逐字复现，结合成员推断、重复检测和敏感信息扫描。

### 189. 模型安全评估包括什么？

包括越狱、违法指导、隐私泄漏、偏见歧视、医疗法律高风险建议、工具滥用和过度拒答测试。

### 190. 安全微调和业务能力如何平衡？

通过分层数据、明确拒答边界、偏好数据校准和业务评估集共同优化，避免只追求安全或只追求可回答。

## 二十、综合面试深挖

### 191. 如果让你从零做一次微调，你会怎么做？

先明确目标和评估标准，选 base model，构造高质量数据，做 chat template 和 label mask 检查，小规模 sanity check，再 LoRA/QLoRA 训练、评估、部署和回归。

### 192. 微调效果差，你会按什么顺序排查？

先查数据格式和 labels，再查推理模板，然后查学习率、训练步数、target_modules、rank、过拟合、数据分布和评估方式。

### 193. 如何判断应该用微调还是 RAG？

需要学习稳定行为、格式和风格时用微调；需要实时、海量、可更新知识时用 RAG。很多业务应两者结合。

### 194. 如何选择 LoRA 还是 QLoRA？

显存足够且追求稳定速度可用 LoRA；显存紧张、模型较大时用 QLoRA，但要接受环境复杂和速度可能变慢。

### 195. 如何选择 SFT 还是 DPO？

模型还不会基本任务或格式时先 SFT；模型已有可用回答但偏好、风格、安全边界不理想时用 DPO。

### 196. 微调时最容易被忽略的工程问题是什么？

最容易忽略 chat template、label mask、EOS、tokenizer 一致性、数据泄漏、checkpoint 可复现和部署时 adapter 是否正确加载。

### 197. 如何控制微调成本？

使用 LoRA/QLoRA、小规模实验、合理 max length、packing、混合精度、gradient checkpointing、早停和高质量数据。

### 198. 如何让微调结果可复现？

固定代码、数据、模型版本、依赖、seed、训练配置和评估集，并保存完整日志与 checkpoint。

### 199. 一个好的微调面试回答应体现什么？

应体现数据质量优先、训练链路细节、显存优化、评估闭环、部署一致性和风险排查，而不是只会说 LoRA。

### 200. 大模型微调的核心主线是什么？

核心主线是用高质量数据和正确训练目标，让模型学会目标行为；用 LoRA/QLoRA 和分布式降低成本；用评估、部署和反馈闭环保证真实可用。
