# 大模型训练参数讲解

训练大模型或微调大模型时，经常会看到一堆参数：learning rate、batch size、epoch、warmup、weight decay、gradient accumulation、max length、bf16、LoRA rank 等。

这些参数不是孤立的。它们共同决定：

- 训练是否稳定；
- 显存是否够；
- 收敛速度；
- 是否过拟合；
- 最终模型效果。

## 一、数据相关参数

### 1. max_seq_length

`max_seq_length` 表示模型一次最多处理多少 token。

```text
max_seq_length = 2048
```

如果样本超过这个长度，会被截断或切分。

影响：

| 影响项 | 说明 |
|---|---|
| 显存 | 长度越大，显存越高 |
| 速度 | 长度越大，训练越慢 |
| 长文本能力 | 长度越大，模型能学习更长上下文 |
| 数据浪费 | 太短会截断有效信息 |

普通 Attention 的复杂度接近 `seq_len^2`，所以长度从 2048 提到 4096，开销不是简单翻倍。

### 2. packing

很多短样本如果单独训练，会浪费 padding。

packing 会把多个短样本拼进一个 sequence：

```text
样本 A + 样本 B + 样本 C -> 一个训练序列
```

优点：

- 减少 padding 浪费；
- 提高 token 利用率；
- 训练速度更高。

注意：需要正确处理不同样本之间的 attention mask 和 labels，避免模型把两个无关样本当成连续文本学习。

### 3. train/eval split

训练集用于更新参数，验证集用于观察泛化效果。

```text
train: 95%
eval: 5%
```

如果只有训练 loss 下降，验证 loss 上升，通常说明开始过拟合。

## 二、Batch 相关参数

### 1. per_device_train_batch_size

每张 GPU 上一次放多少样本。

```text
per_device_train_batch_size = 2
```

它直接影响显存。序列越长、模型越大，能放的 batch 越小。

### 2. gradient_accumulation_steps

梯度累积步数。显存不够时，可以用小 batch 多次前向反向，再统一更新一次参数。

```text
per_device_train_batch_size = 2
gradient_accumulation_steps = 8
```

如果有 1 张 GPU：

```text
effective_batch_size = 2 * 8 = 16
```

如果有 4 张 GPU：

```text
effective_batch_size = 2 * 8 * 4 = 64
```

### 3. effective batch size

有效 batch size 计算公式：

```text
effective_batch_size =
  per_device_train_batch_size
  * gradient_accumulation_steps
  * num_gpus
```

有效 batch size 影响训练稳定性和学习率选择。

一般来说：

- batch 太小：loss 波动大；
- batch 太大：训练更稳定，但可能泛化变差；
- batch 变大时，learning rate 往往也要调整。

## 三、学习率相关参数

### 1. learning_rate

学习率决定每次参数更新的步子有多大。

```text
learning_rate = 2e-5
```

影响：

| 学习率 | 现象 |
|---|---|
| 太大 | loss 爆炸、模型输出变差 |
| 太小 | 收敛慢、学不到任务 |
| 合适 | loss 平稳下降 |

常见范围：

| 场景 | 常见 learning rate |
|---|---|
| 全量微调 | 1e-6 到 5e-5 |
| LoRA 微调 | 1e-5 到 3e-4 |
| 预训练 | 根据规模和 batch 重新设计 |

LoRA 因为只训练少量参数，学习率通常可以比全量微调更大。

### 2. lr_scheduler_type

学习率调度器控制学习率随训练过程变化。

常见类型：

| 类型 | 说明 |
|---|---|
| linear | 线性下降，常见 |
| cosine | 余弦下降，后期更平滑 |
| constant | 固定学习率 |
| constant_with_warmup | warmup 后保持固定 |

线性衰减示意：

```text
lr
|\
| \
|  \
|   \____ step
```

cosine 衰减示意：

```text
lr
|\
| \
|  \__
|     \___ step
```

### 3. warmup_ratio / warmup_steps

训练刚开始时，模型参数还不稳定，如果直接用大学习率，容易震荡。

warmup 会让学习率从 0 慢慢升到目标学习率：

```text
0 -> target learning rate -> decay
```

常见设置：

```text
warmup_ratio = 0.03
warmup_ratio = 0.05
warmup_ratio = 0.1
```

如果总训练步数很少，可以直接设置 `warmup_steps`。

## 四、训练轮数和步数

### 1. num_train_epochs

epoch 表示完整看完训练集几遍。

```text
num_train_epochs = 3
```

对于小数据集：

- epoch 太少：没学会；
- epoch 太多：容易过拟合。

对于大数据集：

- 可能训练 1 个 epoch 都已经很多 step。

### 2. max_steps

`max_steps` 表示最多训练多少更新步。

如果同时设置了 `num_train_epochs` 和 `max_steps`，很多框架会优先使用 `max_steps`。

适合场景：

- 只想快速试跑；
- 数据集很大；
- 需要固定训练预算。

### 3. logging_steps

每隔多少 step 打印一次日志。

```text
logging_steps = 10
```

常看指标：

- train loss；
- learning rate；
- grad norm；
- tokens/sec；
- GPU memory。

## 五、优化器相关参数

### 1. optimizer

常见优化器：

| 优化器 | 说明 |
|---|---|
| AdamW | 大模型训练常用 |
| Adafactor | 内存占用较低 |
| paged_adamw_8bit | QLoRA 常用，省显存 |

AdamW 会保存一阶和二阶动量，所以优化器状态会占不少显存。

### 2. weight_decay

权重衰减是一种正则化，防止参数过大。

```text
weight_decay = 0.01
```

常见范围：

```text
0.0, 0.01, 0.05, 0.1
```

LoRA 微调中，有些配置会使用 0 或较小 weight decay。

### 3. max_grad_norm

梯度裁剪阈值，用于防止梯度爆炸。

```text
max_grad_norm = 1.0
```

如果梯度范数超过阈值，会被缩放。

## 六、精度和显存相关参数

### 1. fp16

使用 FP16 半精度训练。

优点：

- 显存少；
- 速度快。

缺点：

- 数值范围较小；
- 可能出现 loss scale 问题。

### 2. bf16

BF16 也是半精度，但指数范围更大，训练更稳定。

现在如果 GPU 支持 BF16，通常优先用：

```text
bf16 = True
```

### 3. gradient_checkpointing

梯度检查点用于省显存。

普通训练会保存中间激活：

```text
前向保存激活 -> 反向直接用
```

gradient checkpointing 会少保存一些激活，反向时重新计算：

```text
前向少保存 -> 反向重算一部分 -> 省显存但更慢
```

适合显存紧张时使用。

### 4. quantization

量化会把模型权重从 FP16/BF16 降到 INT8、INT4 等。

QLoRA 常见：

```text
load_in_4bit = True
bnb_4bit_quant_type = "nf4"
bnb_4bit_compute_dtype = bf16
```

量化基础模型，训练 LoRA 参数，可以大幅降低显存。

## 七、LoRA 训练参数

### 1. r

LoRA rank，控制低秩矩阵中间维度。

```text
r = 8 / 16 / 32 / 64
```

r 越大：

- 可训练参数越多；
- 表达能力越强；
- 显存和过拟合风险越高。

### 2. lora_alpha

LoRA 缩放系数。

```text
实际缩放 = lora_alpha / r
```

常见配置：

```text
r = 16, alpha = 32
r = 32, alpha = 64
```

### 3. lora_dropout

LoRA 分支上的 dropout。

```text
lora_dropout = 0.05
```

小数据集可以适当加 dropout 防止过拟合；大数据或格式学习任务可以设为 0。

### 4. target_modules

指定哪些线性层插入 LoRA。

常见轻量设置：

```text
["q_proj", "v_proj"]
```

更强设置：

```text
["q_proj", "k_proj", "v_proj", "o_proj",
 "gate_proj", "up_proj", "down_proj"]
```

## 八、保存与评估参数

### 1. save_steps / save_strategy

控制保存 checkpoint 的频率。

```text
save_strategy = "steps"
save_steps = 500
```

保存太频繁会占磁盘；保存太少可能训练中断后损失较大。

### 2. eval_steps / evaluation_strategy

控制验证频率。

```text
evaluation_strategy = "steps"
eval_steps = 500
```

验证集可以帮助判断是否过拟合。

### 3. save_total_limit

最多保留多少个 checkpoint。

```text
save_total_limit = 3
```

防止磁盘被 checkpoint 占满。

## 九、常见参数组合

### 1. 单卡 LoRA 微调参考

```text
per_device_train_batch_size = 2
gradient_accumulation_steps = 8
learning_rate = 2e-4
num_train_epochs = 3
max_seq_length = 2048
bf16 = True
gradient_checkpointing = True
lora_r = 16
lora_alpha = 32
lora_dropout = 0.05
```

### 2. 全量微调参考

```text
per_device_train_batch_size = 1
gradient_accumulation_steps = 16
learning_rate = 1e-5
num_train_epochs = 1-3
bf16 = True
gradient_checkpointing = True
weight_decay = 0.01
max_grad_norm = 1.0
```

全量微调对显存和数据质量要求更高，不建议直接用很大学习率。

## 十、排查训练问题

| 现象 | 可能原因 |
|---|---|
| loss 不下降 | 学习率太小、数据格式错、label mask 错 |
| loss 爆炸 | 学习率太大、精度不稳定、数据异常 |
| 输出重复 | 数据质量差、训练轮数过多、解码参数不合适 |
| 训练很慢 | seq length 太长、batch 太小、未开启 flash attention |
| 显存不够 | batch 太大、seq length 太长、未使用 LoRA/量化/checkpointing |
| 验证 loss 上升 | 过拟合、训练轮数过多、数据太少 |

## 十一、总结

训练参数可以按四类理解：

```text
数据参数: max_seq_length, packing
批次参数: batch_size, gradient_accumulation
优化参数: learning_rate, scheduler, warmup, weight_decay
显存参数: bf16, fp16, quantization, gradient_checkpointing
```

调参时不要一次改太多。更稳妥的方式是：

```text
先小数据跑通
  -> 看 loss 是否正常下降
  -> 再调 batch 和学习率
  -> 再扩大数据和训练步数
```
