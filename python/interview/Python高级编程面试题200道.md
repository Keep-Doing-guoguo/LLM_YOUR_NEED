# Python 高级编程面试题 200 道

本文整理 Python 高级编程相关面试题与参考答案，覆盖对象模型、作用域、装饰器、迭代器、生成器、上下文管理器、描述符、元类、并发、异步、内存管理、类型系统、性能优化、测试、工程化和 Web 后端常见问题。

## 一、Python 语言基础进阶

### 1. Python 是解释型语言吗？

Python 通常被称为解释型语言，但 CPython 会先把源码编译成字节码，再由虚拟机执行。它不是直接逐行解释源码，也不是传统意义上提前编译成本地机器码。

### 2. Python 的执行流程是什么？

源码 `.py` 先被编译成字节码，字节码可缓存为 `.pyc` 文件，然后由 Python 虚拟机逐条执行字节码。

### 3. CPython、PyPy、Jython 有什么区别？

CPython 是官方默认实现，用 C 编写；PyPy 使用 JIT，部分场景更快；Jython 运行在 JVM 上，可与 Java 生态互操作。

### 4. Python 是强类型还是弱类型？

Python 是强类型动态语言。变量类型在运行时确定，但不同类型之间不会随意隐式转换，例如字符串和整数不能直接相加。

### 5. 动态类型是什么意思？

动态类型表示变量本身不绑定固定类型，类型属于对象。变量可以先指向整数，再指向字符串。

### 6. Python 中变量保存的是什么？

变量保存的是对象引用，而不是对象本身。赋值操作本质上是让变量名绑定到某个对象。

### 7. `is` 和 `==` 的区别是什么？

`is` 判断两个变量是否引用同一个对象；`==` 判断两个对象的值是否相等，通常会调用 `__eq__`。

### 8. Python 中一切皆对象是什么意思？

数字、字符串、函数、类、模块都是对象，都有类型、属性和方法，也可以被传递、赋值和存储。

### 9. 可变对象和不可变对象有什么区别？

可变对象创建后内容可变，如 list、dict、set；不可变对象创建后内容不可变，如 int、str、tuple。

### 10. tuple 一定不可变吗？

tuple 本身的元素引用不可变，但如果元素引用的是可变对象，该对象内部内容仍可修改。例如 `([1],)` 中的列表可变。

## 二、作用域与闭包

### 11. Python 的 LEGB 规则是什么？

LEGB 表示变量查找顺序：Local、Enclosing、Global、Builtins。Python 会按这个顺序查找变量名。

### 12. `global` 的作用是什么？

`global` 声明函数内部要使用模块级全局变量，允许在函数内重新绑定该变量。

### 13. `nonlocal` 的作用是什么？

`nonlocal` 声明变量来自外层非全局作用域，常用于闭包中修改外层函数的局部变量。

### 14. 什么是闭包？

闭包是函数和其引用的外部变量环境组合。即使外层函数已经返回，内层函数仍能访问外层变量。

### 15. 闭包常见用途有哪些？

常用于装饰器、函数工厂、延迟计算、保存状态和构造回调函数。

### 16. 闭包中的变量什么时候绑定？

闭包捕获的是变量引用，不是立即拷贝值。循环中创建闭包时常见 late binding 问题。

### 17. 如何解决闭包 late binding 问题？

可使用默认参数绑定当前值，例如 `lambda x, i=i: x + i`，或使用函数工厂创建独立作用域。

### 18. Python 中函数参数默认值什么时候计算？

默认参数在函数定义时计算一次，而不是每次调用都重新计算。

### 19. 为什么不建议用可变对象作为默认参数？

因为默认参数只初始化一次，多次调用会共享同一个对象，可能造成状态污染。

### 20. 如何安全使用可变默认参数？

通常使用 `None` 作为默认值，在函数内部判断并创建新对象。

## 三、函数高级用法

### 21. `*args` 和 `**kwargs` 是什么？

`*args` 接收任意数量的位置参数，形成 tuple；`**kwargs` 接收任意数量的关键字参数，形成 dict。

### 22. Python 函数参数类型有哪些？

包括位置参数、关键字参数、默认参数、可变位置参数、可变关键字参数、仅位置参数和仅关键字参数。

### 23. 仅位置参数是什么？

仅位置参数用 `/` 标记，调用时只能按位置传参，不能使用关键字。

### 24. 仅关键字参数是什么？

仅关键字参数出现在 `*` 之后，调用时必须使用关键字传参。

### 25. 函数是一等对象是什么意思？

函数可以赋值给变量、作为参数传递、作为返回值返回，也可以放入列表、字典等容器。

### 26. 高阶函数是什么？

高阶函数是接收函数作为参数或返回函数的函数，例如 `map`、`filter`、装饰器工厂。

### 27. lambda 的特点是什么？

lambda 是匿名函数，只能包含一个表达式，适合写短小回调，不适合复杂逻辑。

### 28. `functools.partial` 有什么作用？

`partial` 可以固定函数的一部分参数，生成一个新函数，常用于回调和参数预绑定。

### 29. `functools.wraps` 有什么作用？

`wraps` 用于装饰器中保留原函数的 `__name__`、`__doc__`、注解等元信息。

### 30. 函数注解会强制类型检查吗？

不会。Python 的类型注解默认只作为元数据，运行时不强制检查，需要 mypy、pyright 等工具做静态检查。

## 四、装饰器

### 31. 装饰器是什么？

装饰器是在不修改原函数代码的情况下，为函数或类增加额外行为的语法，本质是一个接收对象并返回对象的可调用对象。

### 32. `@decorator` 等价于什么？

`@decorator` 等价于 `func = decorator(func)`，只是语法更简洁。

### 33. 装饰器常见用途有哪些？

常用于日志、权限校验、缓存、重试、事务、性能统计、参数校验和注册机制。

### 34. 带参数装饰器如何实现？

带参数装饰器通常是三层函数：外层接收装饰器参数，中层接收被装饰函数，内层 wrapper 执行增强逻辑。

### 35. 类装饰器是什么？

类装饰器是用于修改或包装类的装饰器，常用于注册类、添加属性、改造方法或实现 dataclass 类似行为。

### 36. 用类实现函数装饰器需要什么？

类需要实现 `__call__`，实例才能像函数一样调用。

### 37. 装饰器会影响函数签名吗？

可能会。如果不使用 `functools.wraps` 或签名保留工具，装饰后函数元信息会变成 wrapper 的信息。

### 38. 多个装饰器的执行顺序是什么？

装饰时从下到上应用，调用时从上到下进入 wrapper。

### 39. 装饰器和中间件有什么相似点？

两者都可以在核心逻辑前后插入通用处理，例如认证、日志和异常处理。

### 40. 装饰器可能带来什么问题？

可能隐藏真实调用链、破坏函数签名、增加调试难度、引入共享状态和造成异常处理不清晰。

## 五、迭代器与生成器

### 41. 什么是可迭代对象？

实现了 `__iter__` 或序列协议的对象可被迭代，例如 list、dict、str、generator。

### 42. 什么是迭代器？

迭代器实现 `__iter__` 和 `__next__`，每次调用 `next()` 返回下一个元素，耗尽时抛出 `StopIteration`。

### 43. 可迭代对象和迭代器有什么区别？

可迭代对象能产生迭代器；迭代器本身保存迭代状态，只能向前消费。

### 44. 生成器是什么？

生成器是包含 `yield` 的函数调用后返回的迭代器，能按需产生值，节省内存。

### 45. `yield` 的作用是什么？

`yield` 暂停函数执行并返回一个值，下次迭代时从暂停位置继续执行。

### 46. 生成器相比列表有什么优势？

生成器惰性计算，不一次性存储所有元素，适合大数据流、无限序列和管道式处理。

### 47. 生成器表达式和列表推导式区别是什么？

生成器表达式惰性产生元素，占用内存低；列表推导式立即生成完整列表。

### 48. `yield from` 有什么作用？

`yield from` 可以把子生成器的值转发给调用方，简化嵌套生成器代码。

### 49. `send()` 可以对生成器做什么？

`send()` 可以向暂停的生成器传入值，并恢复执行，常用于协程风格编程。

### 50. 生成器耗尽后还能重新迭代吗？

不能。生成器是一次性迭代器，耗尽后需要重新创建。

## 六、上下文管理器

### 51. 上下文管理器是什么？

上下文管理器用于管理资源进入和退出逻辑，典型语法是 `with`，常用于文件、锁、连接和事务。

### 52. `with` 语句做了什么？

进入时调用 `__enter__`，退出时调用 `__exit__`，即使发生异常也会执行退出逻辑。

### 53. 如何实现上下文管理器？

可以定义类并实现 `__enter__` 和 `__exit__`，也可以使用 `contextlib.contextmanager` 装饰生成器函数。

### 54. `__exit__` 的返回值有什么意义？

如果 `__exit__` 返回 True，异常会被吞掉；返回 False 或 None，异常继续向外传播。

### 55. `contextlib.contextmanager` 如何工作？

它把一个生成器函数包装为上下文管理器，`yield` 前是进入逻辑，`yield` 后是退出逻辑。

### 56. `contextlib.suppress` 有什么用？

它用于忽略指定异常，让代码更简洁，但应避免吞掉重要错误。

### 57. `ExitStack` 有什么作用？

`ExitStack` 可以动态管理多个上下文管理器，适合资源数量运行时才确定的场景。

### 58. 上下文管理器常见应用有哪些？

文件关闭、数据库事务、线程锁、临时环境变量、计时器、连接池借还和异常边界。

### 59. 异步上下文管理器是什么？

异步上下文管理器实现 `__aenter__` 和 `__aexit__`，通过 `async with` 使用。

### 60. 为什么资源管理要用上下文管理器？

它能保证资源释放逻辑集中且可靠，避免忘记关闭文件、释放锁或回滚事务。

## 七、面向对象高级特性

### 61. Python 中类和实例的关系是什么？

类是创建实例的模板，本身也是对象。实例通过 `__class__` 指向类，类通过 MRO 查找属性和方法。

### 62. 实例属性和类属性区别是什么？

实例属性存储在实例上，类属性存储在类对象上。实例查找属性时会先查实例，再查类和父类。

### 63. `@staticmethod` 是什么？

静态方法不接收 `self` 或 `cls`，只是放在类命名空间中的普通函数。

### 64. `@classmethod` 是什么？

类方法第一个参数是 `cls`，可以访问和修改类级状态，常用于替代构造器。

### 65. `property` 有什么作用？

`property` 把方法包装成属性访问形式，可用于封装计算属性、校验赋值和保持接口稳定。

### 66. `__repr__` 和 `__str__` 区别是什么？

`__str__` 面向用户可读输出；`__repr__` 面向开发调试，理想情况下应尽量明确表达对象状态。

### 67. `__eq__` 和 `__hash__` 有什么关系？

如果两个对象相等，它们的 hash 必须相等。重写 `__eq__` 后通常要谨慎处理 `__hash__`。

### 68. MRO 是什么？

MRO 是 Method Resolution Order，方法解析顺序，决定多继承下属性和方法查找路径。

### 69. Python 使用什么 MRO 算法？

Python 新式类使用 C3 线性化算法，保证局部优先级和单调性。

### 70. `super()` 的作用是什么？

`super()` 按 MRO 调用下一个类的方法，不只是简单调用父类，适合多继承协作。

## 八、魔术方法与对象协议

### 71. 魔术方法是什么？

魔术方法是以双下划线开头和结尾的方法，用于实现对象协议，例如运算符、迭代、上下文管理和属性访问。

### 72. `__new__` 和 `__init__` 区别是什么？

`__new__` 负责创建对象并返回实例，`__init__` 负责初始化已创建的实例。

### 73. 什么时候需要重写 `__new__`？

常见于不可变对象子类、自定义单例、缓存实例和控制对象创建过程。

### 74. `__call__` 有什么作用？

实现 `__call__` 后，对象实例可以像函数一样被调用。

### 75. `__len__` 有什么作用？

它定义对象的长度，可被 `len()` 调用，也会影响对象的布尔值判断。

### 76. `__getitem__` 有什么作用？

它定义索引访问行为，可支持 `obj[key]`、切片和部分迭代场景。

### 77. `__iter__` 有什么作用？

它返回迭代器，使对象可用于 `for` 循环、解包和很多迭代工具。

### 78. `__enter__` 和 `__exit__` 用于什么？

用于实现同步上下文管理器，支持 `with` 语句。

### 79. `__getattr__` 和 `__getattribute__` 区别是什么？

`__getattribute__` 对所有属性访问都会调用；`__getattr__` 只在正常查找失败时调用。

### 80. 重写 `__getattribute__` 有什么风险？

容易造成无限递归，必须通过 `object.__getattribute__` 访问真实属性。

## 九、描述符、元类与 Dataclass

### 81. 描述符是什么？

描述符是实现了 `__get__`、`__set__` 或 `__delete__` 的对象，用于控制属性访问。

### 82. 数据描述符和非数据描述符区别是什么？

实现 `__set__` 或 `__delete__` 的是数据描述符，优先级高于实例字典；只实现 `__get__` 的是非数据描述符。

### 83. `property` 是描述符吗？

是。`property` 通过描述符协议控制属性读取、设置和删除。

### 84. 方法为什么会自动绑定 self？

函数作为类属性时是非数据描述符，从实例访问时会返回绑定方法，把实例绑定为第一个参数。

### 85. 元类是什么？

元类是创建类的类。普通对象由类创建，类对象由元类创建，默认元类是 `type`。

### 86. 元类有什么用途？

可用于控制类创建过程、注册子类、校验类定义、自动添加方法和实现 ORM 模型声明。

### 87. `__init_subclass__` 有什么作用？

它在子类创建时自动调用，可用于子类注册、校验配置和框架扩展，比元类更轻量。

### 88. `dataclass` 有什么作用？

`dataclass` 自动生成 `__init__`、`__repr__`、`__eq__` 等方法，适合定义数据容器类。

### 89. `dataclass(frozen=True)` 表示什么？

表示实例创建后字段不可重新赋值，接近不可变对象，但如果字段内部是可变对象仍需小心。

### 90. `attrs` 和 `dataclass` 有什么关系？

`attrs` 是更早、更强大的第三方数据类库；`dataclass` 是标准库提供的轻量方案。

## 十、异常处理

### 91. Python 异常处理流程是什么？

异常抛出后沿调用栈向上查找匹配的 `except`，若无人处理则程序终止并打印 traceback。

### 92. `try/except/else/finally` 各自作用是什么？

`try` 放可能出错代码，`except` 处理异常，`else` 在无异常时执行，`finally` 无论是否异常都会执行。

### 93. 为什么不要裸 `except:`？

裸 `except` 会捕获所有异常，包括 KeyboardInterrupt、SystemExit，容易掩盖严重问题。

### 94. 自定义异常有什么好处？

能表达业务错误类型，让调用方精确捕获和处理，提高代码可读性。

### 95. `raise from` 有什么作用？

`raise new_exc from old_exc` 可以保留异常链，说明新异常由旧异常引起，便于排查。

### 96. 异常和返回错误码如何选择？

异常适合处理非正常流程和错误传播；错误码适合性能敏感或预期内频繁发生的状态。

### 97. finally 中 return 有什么风险？

finally 中的 return 会覆盖 try 或 except 中的 return 或异常，容易隐藏错误。

### 98. 如何设计异常层次？

为模块定义基础异常类，再按业务错误细分，避免直接抛出过于泛化的 Exception。

### 99. EAFP 是什么？

EAFP 是 Easier to Ask Forgiveness than Permission，先执行再捕获异常，是 Python 常见风格。

### 100. LBYL 是什么？

LBYL 是 Look Before You Leap，执行前先检查条件。它可读性高，但并发场景可能有竞态。

## 十一、内存管理与垃圾回收

### 101. Python 内存管理主要机制是什么？

CPython 主要使用引用计数管理对象生命周期，并辅以分代垃圾回收处理循环引用。

### 102. 引用计数是什么？

每个对象记录有多少引用指向它。当引用计数降为 0 时，对象通常会立即被释放。

### 103. 循环引用是什么？

两个或多个对象相互引用，即使外部没有引用，它们的引用计数也不为 0，需要垃圾回收器检测。

### 104. 分代垃圾回收是什么？

Python 把对象分为不同代，新对象在年轻代，存活越久越可能进入老年代，年轻代更频繁回收。

### 105. `gc` 模块有什么用？

`gc` 模块可手动触发垃圾回收、查看 GC 阈值、调试循环引用和不可回收对象。

### 106. `__del__` 有什么风险？

对象销毁时调用顺序不稳定，循环引用中带 `__del__` 的对象处理复杂，可能导致资源释放不可预测。

### 107. 如何更可靠地释放资源？

使用上下文管理器、显式 close、try/finally 或 weakref finalizer，而不是依赖 `__del__`。

### 108. 浅拷贝和深拷贝区别是什么？

浅拷贝只复制外层容器，内部对象仍共享；深拷贝递归复制内部对象。

### 109. `copy.copy` 和 `copy.deepcopy` 有什么区别？

`copy.copy` 做浅拷贝，`deepcopy` 递归复制对象图，并处理循环引用。

### 110. 弱引用是什么？

弱引用不会增加对象引用计数，可用于缓存、观察者模式和避免循环引用。

## 十二、GIL 与多线程

### 111. GIL 是什么？

GIL 是 Global Interpreter Lock，CPython 中保证同一时刻只有一个线程执行 Python 字节码的全局锁。

### 112. GIL 为什么存在？

它简化了 CPython 的内存管理和 C 扩展实现，保护对象引用计数等内部状态。

### 113. GIL 对 CPU 密集型任务有什么影响？

多线程无法真正并行执行 Python 字节码，CPU 密集任务通常不能靠多线程充分利用多核。

### 114. GIL 对 IO 密集型任务影响大吗？

相对较小。线程在等待 IO 时会释放 GIL，因此多线程适合网络、文件、数据库等 IO 密集任务。

### 115. 如何绕过 GIL 做 CPU 并行？

可使用多进程、C 扩展释放 GIL、NumPy 向量化、Cython、Numba 或把计算交给外部服务。

### 116. `threading.Lock` 有什么作用？

锁用于保护共享状态，避免多个线程同时修改导致竞态条件。

### 117. RLock 和 Lock 区别是什么？

RLock 是可重入锁，同一线程可重复获取；普通 Lock 重复获取会死锁。

### 118. Condition 有什么作用？

Condition 用于线程间等待和通知，适合生产者消费者等协作场景。

### 119. Queue 为什么适合线程通信？

`queue.Queue` 是线程安全队列，内置锁和条件变量，适合在线程间传递任务。

### 120. 线程池有什么好处？

线程池复用线程，减少频繁创建销毁开销，并可限制并发数量。

## 十三、多进程与并行计算

### 121. multiprocessing 适合什么场景？

适合 CPU 密集型任务，因为每个进程有独立解释器和 GIL，可利用多核。

### 122. 多进程的代价是什么？

进程创建、上下文切换、内存占用和进程间通信成本较高。

### 123. fork、spawn、forkserver 有什么区别？

fork 复制当前进程，快但可能继承不安全状态；spawn 启动新解释器，更安全但慢；forkserver 通过服务进程 fork。

### 124. Windows 上为什么需要 `if __name__ == "__main__"`？

Windows 默认使用 spawn，子进程会重新导入主模块，缺少保护可能递归创建进程。

### 125. 进程间通信有哪些方式？

常见有 Queue、Pipe、Manager、共享内存、文件、socket 和消息队列。

### 126. multiprocessing.Queue 和 queue.Queue 区别是什么？

`queue.Queue` 用于线程间通信，`multiprocessing.Queue` 用于进程间通信。

### 127. ProcessPoolExecutor 是什么？

它是 `concurrent.futures` 提供的进程池接口，简化多进程任务提交和结果获取。

### 128. 多进程为什么要注意序列化？

进程间传递对象通常需要 pickle 序列化，不能序列化的对象无法直接传递。

### 129. 共享内存适合什么场景？

适合多进程共享大数组或大块数据，减少复制和序列化开销。

### 130. CPU 密集任务如何选择线程还是进程？

在 CPython 中通常选择多进程或原生扩展；多线程更适合 IO 密集任务。

## 十四、异步编程

### 131. asyncio 是什么？

asyncio 是 Python 标准库的异步 IO 框架，基于事件循环和协程实现高并发 IO。

### 132. 协程是什么？

协程是可暂停和恢复的函数，使用 `async def` 定义，通过 `await` 等待异步操作。

### 133. event loop 是什么？

事件循环负责调度协程、处理 IO 事件、定时器和任务回调，是 asyncio 的核心。

### 134. `await` 做了什么？

`await` 暂停当前协程，把控制权交还事件循环，等待 awaitable 完成后恢复执行。

### 135. task 和 coroutine 有什么区别？

coroutine 是协程对象，本身不会自动运行；task 是被事件循环调度执行的协程包装。

### 136. `asyncio.gather` 有什么作用？

它并发执行多个 awaitable，并按输入顺序返回结果。如果一个任务异常，默认会传播异常。

### 137. `asyncio.create_task` 有什么作用？

它把协程注册为 Task，让其在事件循环中并发运行。

### 138. 异步函数里能不能直接调用阻塞函数？

不建议。阻塞函数会卡住事件循环，应使用异步库或通过线程池/进程池执行。

### 139. asyncio 适合 CPU 密集任务吗？

不适合。asyncio 主要解决 IO 并发，CPU 密集任务会阻塞事件循环。

### 140. async with 和 async for 分别用于什么？

`async with` 用于异步上下文管理器，`async for` 用于异步迭代器。

## 十五、类型系统与泛型

### 141. Python 类型注解的作用是什么？

类型注解提升可读性、IDE 提示和静态检查能力，但默认不在运行时强制执行。

### 142. mypy 和 pyright 是什么？

它们是 Python 静态类型检查工具，用于在运行前发现类型错误。

### 143. `Optional[T]` 表示什么？

`Optional[T]` 表示值可以是 `T` 或 `None`，等价于 `T | None`。

### 144. `Union` 表示什么？

`Union[A, B]` 表示值可以是 A 或 B 类型。Python 3.10 后可写成 `A | B`。

### 145. `Any` 有什么风险？

`Any` 会绕过类型检查，过度使用会让类型系统失去价值。

### 146. `Protocol` 是什么？

Protocol 支持结构化子类型，只要对象具有协议要求的方法和属性，就可视为满足该类型。

### 147. `TypeVar` 有什么作用？

TypeVar 用于定义泛型函数或泛型类，让输入和输出类型之间保持关系。

### 148. `Generic` 有什么作用？

Generic 用于定义泛型类，例如 `class Box(Generic[T])`。

### 149. TypedDict 是什么？

TypedDict 用于给字典定义固定键和对应值类型，适合描述 JSON 风格数据。

### 150. dataclass 和 Pydantic 有什么区别？

dataclass 主要是轻量数据容器；Pydantic 提供运行时数据校验、解析和序列化，更适合 API 输入输出。

## 十六、模块、包与导入机制

### 151. Python 模块是什么？

模块是一个 Python 文件或扩展模块，导入后成为模块对象，可包含变量、函数和类。

### 152. 包是什么？

包是包含模块的目录，通常有 `__init__.py`，用于组织命名空间。

### 153. Python 导入模块时做了什么？

查找模块、加载源码或字节码、执行模块顶层代码、创建模块对象并缓存到 `sys.modules`。

### 154. `sys.modules` 有什么作用？

它缓存已导入模块，后续 import 会优先复用，避免重复执行模块代码。

### 155. 循环导入为什么会出问题？

两个模块互相导入时，可能访问到尚未初始化完成的模块对象，导致属性不存在或导入失败。

### 156. 如何解决循环导入？

可重构依赖、延迟导入、抽取公共模块、使用接口反转或把导入放到函数内部。

### 157. `importlib` 有什么作用？

`importlib` 支持运行时根据字符串动态导入模块，常用于插件系统、动态加载和框架扩展。

### 158. `__all__` 有什么作用？

`__all__` 控制 `from module import *` 导入哪些名称，也能表达模块公开 API。

### 159. 相对导入和绝对导入区别是什么？

绝对导入从顶层包路径查找；相对导入用点号表示当前包内相对位置。

### 160. 为什么不建议滥用 `from module import *`？

它会污染命名空间，降低可读性，可能覆盖已有变量，静态分析也更困难。

## 十七、性能优化

### 161. Python 性能瓶颈常见来源有哪些？

常见包括 Python 层循环、频繁函数调用、重复 IO、低效数据结构、锁竞争、序列化和不必要的对象创建。

### 162. 如何定位性能瓶颈？

先用 profiling 工具定位，如 cProfile、py-spy、line_profiler，再针对热点优化，不要凭感觉优化。

### 163. cProfile 有什么作用？

cProfile 统计函数调用次数和耗时，适合定位函数级性能瓶颈。

### 164. timeit 有什么作用？

timeit 用于对小段代码做相对稳定的微基准测试，避免一次性计时误差。

### 165. Python 中列表和生成器如何选择？

需要多次访问或随机访问时用列表；只需顺序消费、大数据流或节省内存时用生成器。

### 166. list、set、dict 查找复杂度如何？

list 查找通常 O(n)，set 和 dict 平均 O(1)，但依赖哈希和冲突情况。

### 167. 为什么字符串拼接建议用 join？

大量循环拼接字符串会创建许多临时对象；`''.join(parts)` 通常更高效。

### 168. NumPy 为什么比 Python 循环快？

NumPy 把计算放到底层 C/Fortran 向量化实现中，减少 Python 解释器循环开销。

### 169. LRU Cache 是什么？

LRU Cache 缓存最近使用的函数结果，适合纯函数和重复计算场景，可用 `functools.lru_cache`。

### 170. 过早优化有什么问题？

可能让代码复杂化却没有实际收益。应先保证正确性，再基于 profiling 优化热点。

## 十八、测试、调试与工程质量

### 171. 单元测试和集成测试区别是什么？

单元测试验证小函数或类；集成测试验证多个模块、数据库、网络或外部系统协作。

### 172. pytest 的优势是什么？

pytest 语法简洁，fixture 强大，插件丰富，断言信息友好，适合中大型项目测试。

### 173. fixture 是什么？

fixture 用于提供测试前置资源和清理逻辑，例如数据库连接、临时文件、测试客户端。

### 174. mock 有什么作用？

mock 用于替代外部依赖、网络请求、时间、随机数或复杂对象，让测试更稳定和可控。

### 175. monkeypatch 是什么？

pytest 的 monkeypatch 可临时修改属性、环境变量、路径或函数，测试结束后自动恢复。

### 176. 如何测试异常？

pytest 中可使用 `pytest.raises(ExpectedError)` 断言某段代码会抛出指定异常。

### 177. logging 相比 print 有什么优势？

logging 支持级别、格式、输出位置、结构化日志和按模块配置，适合生产环境。

### 178. pdb 有什么作用？

pdb 是 Python 内置调试器，可设置断点、单步执行、查看变量和调用栈。

### 179. 类型检查和测试是什么关系？

类型检查能提前发现部分错误，测试验证运行时行为。两者互补，不能互相替代。

### 180. 代码格式化工具有哪些？

常见有 black、ruff format、isort。ruff 还可做 lint 和部分自动修复。

## 十九、Web 与后端工程

### 181. WSGI 是什么？

WSGI 是 Python Web 服务器和同步 Web 应用之间的标准接口，Flask、Django 传统部署常用。

### 182. ASGI 是什么？

ASGI 是支持异步、WebSocket 和长连接的接口标准，FastAPI、Starlette、Django Channels 常用。

### 183. Flask 和 FastAPI 的主要区别是什么？

Flask 轻量灵活，默认同步；FastAPI 基于类型注解和 ASGI，自动生成 OpenAPI，原生支持异步。

### 184. ORM 是什么？

ORM 把数据库表映射为 Python 对象，让开发者通过对象操作数据库，减少手写 SQL。

### 185. ORM 的优缺点是什么？

优点是开发效率高、模型清晰；缺点是复杂查询可能低效，容易隐藏 N+1 查询和 SQL 性能问题。

### 186. N+1 查询是什么？

先查一批主对象，再对每个对象单独查关联数据，导致大量额外 SQL。可用预加载或 join 优化。

### 187. 数据库连接池有什么作用？

连接池复用数据库连接，减少频繁创建连接开销，并限制最大连接数保护数据库。

### 188. Session、Cookie、Token 有什么区别？

Cookie 存在客户端；Session 通常服务端保存会话状态，客户端用 cookie 存 session id；Token 常是自包含或可验证凭证。

### 189. JWT 有什么优缺点？

JWT 无状态、易跨服务验证，但一旦签发不易主动失效，载荷过大也会增加请求成本。

### 190. Web 后端如何处理并发请求？

同步框架通常靠多进程/多线程 worker；异步框架靠事件循环处理 IO 并发，CPU 密集任务仍需进程池或外部服务。

## 二十、综合面试深挖

### 191. Python 项目如何组织目录？

通常按包组织源码，区分应用代码、测试、配置、脚本和文档。中大型项目可使用 `src/` 布局，避免导入路径混乱。

### 192. `requirements.txt` 和 `pyproject.toml` 区别是什么？

`requirements.txt` 常用于固定安装依赖；`pyproject.toml` 是现代 Python 项目的统一配置文件，可声明构建系统、依赖和工具配置。

### 193. 虚拟环境有什么作用？

虚拟环境隔离项目依赖，避免不同项目包版本冲突，提升部署和复现稳定性。

### 194. 如何保证 Python 服务线上稳定？

需要日志、监控、异常告警、健康检查、超时、重试、限流、配置管理、测试覆盖和可回滚发布。

### 195. Python 中如何设计插件系统？

可使用注册表、装饰器注册、entry points、importlib 动态导入和统一接口协议。

### 196. 如何设计一个可维护的 Python 类？

职责单一，接口清晰，避免过深继承，组合优先，类型注解明确，异常语义清楚，并配套测试。

### 197. Python 代码 review 重点看什么？

看正确性、异常处理、边界条件、可读性、复杂度、测试、性能热点、并发安全和依赖安全。

### 198. 高级 Python 面试最常考什么？

常考对象模型、装饰器、生成器、上下文管理器、描述符、GIL、异步、多进程、内存管理、导入机制和工程化经验。

### 199. 如何回答 Python 性能优化问题？

先强调 profiling 定位瓶颈，再从算法、数据结构、IO、缓存、并发、向量化、C 扩展和部署架构逐层优化。

### 200. Python 高级编程的核心主线是什么？

核心主线是理解对象和协议、掌握函数式与 OOP 机制、正确处理并发和资源、写可测试可维护的工程代码，并用工具定位真实问题。
